## 第 2 轮：我否定了验收结论

> **我的 Prompt（2026-10-16 13:03）：**
> 「没有曲线删除啊」

AI 的第一反应不是重写代码，而是**逐帧抓取**（0 / 60 / 120 / 180 / 240ms）：

> 「动画**是在跑**（各帧都不同，条目在倾斜、上移、然后下落淡出），但你的感觉是对的：**它看起来不像一条曲线**。」

根因判断：这是一行约 1400px 宽的条目，位移只有 38px（约 2.7%），四个关键帧之间的默认缓动叠加后，视觉上只是"轻轻歪一下然后淡出"。

**这一轮暴露的是我的判断维度的问题，不是 AI 的**：我说"没有"，准确说是"有但读不出来"。AI 没有顺着我说"确实没有"，而是先把事实摆出来，再接受我的结论。

**修复尝试 1 失败**：加了 `overflow: hidden` 裁剪 + 2° 旋转。AI 自己发现：

> 「旋转太大了（2° 在 1300px 宽的行上看起来像整行歪掉了，不像曲线）。而且向上的弧会撞到上面的摘要文字。」

**修复尝试 2**：几乎不旋转，改成"向右滑出 + 下沉的弧"。这次 AI 做了**路径量化**而不是看截图：

| t (ms) | dx | dy | dy/dx |
|---|---|---|---|
| 50 | 20 | 2 | 0.10 |
| 150 | 107 | 9 | 0.09 |
| 200 | 209 | 41 | 0.31 |
| 250 | 322 | 80 | 0.36 |
| 350 | 358 | 92 | ~0.25 |

> 「斜率从 0.09 升到 0.36 再回落——向右滑出的同时**后半程明显下坠**，是条实打实的弧。」

## 第 3 轮：真正的 bug 浮出水面

> **我的 Prompt（2026-10-16 13:12）：**
> 「刚把动画效果打开，可以看到动效了，但是删除还是直接消失」

**这句话是整个项目的转折点。** 它描述的是一个几乎不可能是巧合的组合：*别的动画都好了，只有删除立刻消失*。

> **AI 的判断：** 「能看到其他动效但删除直接消失——这个组合很可疑。我怀疑是 `REDUCE_MOTION` 在页面加载时被**快照**成了常量……CSS 媒体查询是实时的、所以其他动效正常了。」

**关键在于 AI 说的是"我怀疑……先写个复现测试确认，不猜"。**

复现测试确认了故障：

- 点击删除瞬间，浏览器实时媒体查询是 `false`（**允许动画**）
- 但代码仍把条目立即移除（`itemsAt60ms: 3`、`leavingClassAt60ms: false`）

**根因代码：**

```js
const REDUCE_MOTION = window.matchMedia('(prefers-reduced-motion: reduce)').matches;  // ← 加载时快照
const ITEM_OUT_MS = REDUCE_MOTION ? 0 : 400;
```

| | 加载时 | 之后用户打开动画 | 结果 |
|---|---|---|---|
| CSS 媒体查询 | reduce | **实时变回 no-preference** | 其他动效恢复 ✓ |
| JS 常量 `REDUCE_MOTION` | `true` | **仍是 `true`**（永不更新） | 删除走"跳过动画"分支 → **瞬逝** ✗ |

**修复：**

```js
function prefersReduce() { return reduceMQ.matches; }   // 每次删除时现查，不再快照
```

**双场景验证：**

| 场景 | 修复前 | 修复后 |
|---|---|---|
| 加载时 reduce → 之后打开动画（不刷新） | 直接消失 ✗ | 正常播放弧线 ✓ |
| 真实 reduce 环境 | 跳过 ✓ | 跳过 ✓（正确行为） |
| 正常环境 | 正常 ✓ | 正常 ✓，无残留 transform |

产物：commit `faedab6`。

## 这条链证明了什么

这是赛道评分表里两个维度同时要的东西：

**① 过程可复现性（25%）** —— 整个 bug 的因果链是可以被第三人独立走一遍的：贴出根因代码 → 给出复现条件（reduce 下加载、不刷新切回 no-preference、点删除）→ 给出修复前后对比表。评委不需要相信我，照着做就能复现。

**② 对 AI 的约束能力（20%）** —— 三轮里 AI 有三次自然的错误路径：

| AI 的倾向 | 被什么挡住 |
|---|---|
| 第一轮宣称"动画播完"验收通过 | 我在真机上否定了它 |
| 第一轮把"没有曲线"当需求不明确直接重写 | 它选择先逐帧取证，再接受结论 |
| 定位到快照问题后直接改 | 它先写复现测试确认，再改 |

**我没有靠"再改一下"推进，而是靠提供一条反常的事实（"其他动效好了，只有删除不行"）。** 这条事实的信息量远大于"还是不对"——它把搜索空间从"动画代码"直接压缩到了"这段代码和其他动效的差异"，而那个差异就是常量快照。
