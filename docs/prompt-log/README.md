## 每条链的固定结构

```
第 1 轮  我的 Prompt（原文引用）
         ↓
         AI 的取证与判断（不是直接改代码）
         ↓
第 2 轮  我的反馈（通常是"反例"，不是"指令"）
         ↓
         改动落点 + 回归验证
         ↓
提交
         ↓
这条链证明了什么 + 怎么自己复现
```

轮次按实际对话走，不强行凑三轮：02 有三轮，03 只有一轮症状 + 一次提交。

---

## 一个贯穿三条链的约定

**判断权在我，实现权在 AI。** 三条链里我从来不写"你应该怎么改"，只提供三样东西:

1. **一条反常的事实**（"其他动效都好了，只有删除不行"；"全屏放大或者缩小时会出现有些颜色变成黑色"）
2. **一段真实的失败样本**（那句"没有曲线删除啊"、那次全屏缩放后的黑块）
3. **一次把主观反馈逼成具体方案的要求**（"有些刺眼" → 四组具体色值、高饱和面积砍到 1/4；"没有曲线删除啊" → 逐帧冻结 + 路径量化）

实现细节、根因定位、回归用例，全部由 AI 给出，再由我在浏览器里验。**这就是本项目的"意图控制"策略——不控制代码，控制输入的事实和验收的标准。**

## 对应的仓库约定

这些协作方式被固化在仓库的 [`AGENTS.md`](../../AGENTS.md) 里，AI 每次开工前先读它：

- 规则集中在 `app.js` 顶部的常量与 `extract()` / `extractAll()` 附近，**不许散落到渲染代码**
- 日期落点集中在 `resolveDeadline()` / `ensureDueDates()`
- AI 提示词与输出校验集中在 `buildAIExtractPrompt()` / `parseAIItems()` / `aiExtract()`
- 必须在浏览器里实际打开验证，**不能只读代码判断"应该能跑"**
- 每条待办都要能说出"为什么"被提取（命中了哪个关键词或时间）

**这三条链之所以能保持在可控范围内，靠的就是这份文件，而不是靠每次临时提醒。**
