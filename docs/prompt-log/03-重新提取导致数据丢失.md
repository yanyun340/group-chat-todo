## 第 1 轮：一句没有复现步骤的报错

> **我的 Prompt（2026-10-20 21:42）：**
> 「我发现有时候导入了新的事情原先的事情会消失」

**注意这句话的形态：没有输入样本、没有截图、没有复现步骤，只有一句感受。** 这是最考验"AI 能不能把它当成真问题"的输入。

AI 没有要求我补材料，也没有说"无法复现"，而是直接从代码结构定位：

> 「已修好，问题出在重新提取时把整批条目**替换**了，而不是追加。」

根因：`applyExtractResult()` 里 `items = list` 覆盖。

**修复内容：**

- 新导入的条目改为**追加**到现有清单，不再覆盖
- 同一件事（去掉标点空白后正文相同）跳过；已有条目的完成状态、手动排期、排序都保留
- 这次没识别到新待办时，只提示「原有 N 条都保留着」，不清空
- 空输入只提示，不再清空清单
- 每条待办记住自己的 `importedAt`；相对日期（明天/周五）改为**以各自条目的导入时间为锚点**，后导入的批次不会改写先前条目的日期
- AI 提取成功、AI 失败回退本地规则，走**同一套**追加逻辑

**这一条顺手修掉了一个更深的问题**：原先「明天下午 5 点」是相对**最近一次提取时刻**计算的。改为按条目自己的导入时间锚定之后，同一批聊天反复打开，日期不会再漂移。

**回归验证用了十种场景**（含"导入 A → 标记完成 → 导入 B"、"重复导入 A"、"空输入"、"无待办"、"日历手动添加"、"刷新"、"AI 失败回退"、"AI 返回空"），全部通过。

## 第 2 轮：我自己又抓到一个

> **我的 Prompt（2026-10-20 22:02）：**
> 「我说周六周天要打球ai给我放进了待确认，不应该是待办吗」

AI 的判断：**这是规则漏了，不是判错了。**

> 「本地规则只认「提交 / 报名 / 开会」这类任务动词，`打球` 不在动作词表里，于是「周六周天要打球」只认出了时间、认不出"要做的事"，就掉进了「待确认」。」

**修复：**

- 新增活动词表：`打球 / 打羽毛球 / 打篮球 / 踢球 / 跑步 / 游泳 / 健身 / 爬山 / 看电影…`。命中有明确时间即判为待办，依据显示成「活动「打球」」而不是笼统的"关键词"
- **取消通知收紧**：即使句子里有动作/活动词，「周六考试取消了」「周末打球取消」也不会被当成待办；但「记得取消场地」「帮我取消预约」这种**让人去取消**的话仍然保留
- AI 提示词第 7 条补上"群里约好的活动只要带明确时间就是 todo"，**提示词版本升到 `3`**，旧缓存自动失效
- 重新提取时，若原条目在「待确认」而这次已明确判成待办，**自动转正**（已完成的不动）——否则旧的误判重新提取多少遍都卡在原处

**九组输入验证**，包括「周六周天要打球 / 周六周日要打球 / 周六、周日要打球」三种写法、疑问句「周六周天要打球吗」不提取、取消通知不产生条目。

## 这条链证明了什么

**① AI 协商里最容易被糊弄的输入，AI 没有糊弄。** 「有时候会消失」这种描述在绝大多数 AI 会话里会被要求"提供复现步骤"然后卡住。这里 AI 选择去读代码定位覆盖点，然后**用十种场景自己把复现步骤造出来验证**。

**② 我提供的是"反例"，不是"指令"。** 两轮我都没有说"你应该怎么做"，只说了"它现在做错了，错在哪"。**判断权在我，实现权在 AI**——这正是赛道要考察的"意图对齐"。

**③ 修一个 bug 带出一个设计修正。** 「重新提取替换清单」这个 bug 修完之后，顺带把"相对日期该以谁为锚点"这个设计问题定死了：**每条条目以自己的导入时间为锚**。这不是补丁，是规则的确立，并且写进了 README 的边界说明。

**④ AI 主动收窄了自己的修复范围。** 加活动词表时，它同时处理了反向情况（取消通知），而不是只满足我提的那一句。这是"意图边界"和"字面指令"的区别。
