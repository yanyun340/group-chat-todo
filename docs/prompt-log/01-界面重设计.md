## 第 1 轮：我只给了一句约束，没有给任何具体指令

> **我的 Prompt（原文，2026-10-15 22:57）：**
> 「采用非常规的布局方式，使用不和谐的色彩和字体，同时让负空间显得有些不对称，打破所有规则，但仍然让页面看起来很棒。 再设计一下」

**这句话里没有一个颜色值、没有一个像素、没有一个组件名。** 它是四条互相拉扯的约束：

1. 布局要"非常规"
2. 色彩和字体要"不和谐"
3. 负空间要"不对称"
4. 但要"打破所有规则，仍然好看"

第 4 条是真正难的地方——前三条都在说"破坏"，第 4 条说"破坏完还得成立"。

### AI 把它翻译成了可执行的东西

> 「用户要"打破规则但仍好看"，这正好是刻意的撞色 + 硬描边 + 不对称，**但每处都得有意图，不能真乱**。」

这句话是整条链的核心。它没有把"打破规则"理解成随机，而是理解成**每一条规则被打破时都要有理由**。落地成七条具体手法：

| 抽象要求 | 具体手法 |
|---|---|
| 不和谐的色彩 | 酸柠绿 `#D9FF3D` × 钴蓝 `#2B3CFF` × 荧光粉 `#FF4B8C` × 薄荷 `#2EE6A8`，**每种只负责一个语义**（待办/相关/待确认/已完成）——撞而不乱 |
| 非常规布局 | 硬描边 + **无 blur 的 `5px 5px 0` 实心偏移阴影**，卡片像从纸上"凸"出来的硬纸板 |
| 不和谐的字体 | 三种混搭：大标题衬线斜体 + 正文无衬线 + 标签等宽 mono |
| 不对称负空间 | `padding: 0 3.5vw 0 7vw`（左大右小）；当时右侧输入台整体下移 44px（后续版本改成吸顶跟随）；统计块右下角**故意留一个空格** |
| 仍然好看 | 动效仍然只用 `transform` / `opacity`；`prefers-reduced-motion` 降级不变；纯 CSS 无框架 |

**注意最后一行**：它在追求视觉突破的同时，自己把工程底线守住了——没有为了"炸"去用 JS 动画、没有引入框架、没有破坏无障碍。

### 它先验证，再提交

> 「四张图都无溢出，结构成立。用 vision 交叉验证一下桌面填充态有没有真实缺陷。」
>
> 「无真实缺陷。」

产物：`61f3bb4`，`index.html` 176 行改动、`styles.css` 787 行改动（+470/−495）。

## 第 2 轮：我说"有些刺眼"

> **我的 Prompt（原文，2026-10-15 23:05）：**
> 「有些刺眼，然后："还没有结果 贴一段群聊记录，点「提取待办」开始"这一块方格没有用，给我一下修改方案，大概就行」

**"有些刺眼"是一个几乎无法执行反馈。** 哪里刺？刺多少？压到什么程度？

AI 没有直接改代码，先做了归因：

> 「根源是 **4 个统计块全是大面积 100% 饱和荧光色**，加上标题投影和背景斜带都在高饱和，叠一起晃眼。改法：**色相不变、饱和度和明度各降一档，亮色只留给小面积**。」

它的方案有一个名字：**「压色不换骨」**。

| 元素 | 现在（刺） | 改后（耐看） |
|---|---|---|
| 酸柠绿 | `#D9FF3D` | 芥末黄 `#D9B64A` |
| 钴蓝 | `#2B3CFF` | 靛蓝 `#3B4C9E` |
| 荧光粉 | `#FF4B8C` | 陶土 `#CB6E5E` |
| 薄荷 | `#2EE6A8` | 灰绿 `#74B293` |

配套三刀：

1. **大统计块**：只留「待办」大块带色，其余三个改**白底 + 各自色描边 + 数字用色**——高饱和实心面积直接砍到 1/4
2. **标题投影**：酸绿 → 芥末黄
3. **背景斜带**：粉色那条去掉，剩下的降 opacity，只留一条很淡的斜带

> 「这样硬描边、硬阴影、不对称、字体混搭全保留，neo-brutalism 的"粗"还在，**但不辣眼睛了**。」

> **我的回应（2026-10-15 23:07）：** 「按你这个做」

产物：`c275340`。

## 第 3 轮：同一句话里还有第二个问题

我在那句反馈里顺带提了另一件事：「"还没有结果…"这一块方格没有用」。

AI 给了三个方案并说明取舍：

- **A. 直接删掉**——最省事，但**不推荐**：「不对称布局下左边会空一大片，反而难看」
- **B. 改成"一键体验"卡（推荐）**：占位区变成引导卡，一个大按钮「填入示例并提取」，点击 = 自动填示例 + 提取
- **C. 改成静态"能力说明卡"**：适合答辩讲解，但不如 B 直接

它推荐 B，理由写得很直接：

> 「把"空态"从"没内容"变成"入口"，既填了空白又降低了试用门槛——**对考核场景尤其有用（评审不会耐心先读说明书）**。」

**它在为我的使用场景做判断，而不是只回答"这块要不要删"。**

## 这条链证明了什么

**① 抽象约束能不能被翻译成可执行的规则，是 AI 协作的分水岭。**
"打破所有规则但仍然好看"这种话，交给一个只会听话的模型，会得到一版随机撞色；这里它先给了一个判断——「每处破例背后都要有意图」——然后才落地成七条手法。**先立原则、再出方案**，这是我在整个项目里最想复制给 AI 的工作方式。

**② 第一版做过头是正常的，关键是收敛能力。**
荧光版确实刺眼。但如果第一版就保守，这个界面永远不会长出现在这样。真正的能力在于：我说"有些刺眼"四个字，它能归因到"大面积 100% 饱和色"，并给出"压色不换骨"——**保留结构，只换参数**。

**③ 它在追求视觉突破时没有牺牲工程底线。**
动效仍然只用 `transform` / `opacity`、`prefers-reduced-motion` 降级保留、纯 CSS 无框架、双击即开。**"炸"从不以破坏可用性为代价。**

**④ 它把模糊需求翻译成了我的使用场景。**
占位区那三个方案里，它推荐 B 的理由不是"更好看"，而是"评审不会耐心先读说明书"。这不是审美判断，是**对我要拿这个东西去干什么的判断**。
