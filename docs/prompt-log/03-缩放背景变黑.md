## AI 的取证与判断

AI 没有把锅甩给浏览器、显卡或“偶现”，而是直接读 `bg-shader.js` 的 resize 路径：

**AI 当时的判断：**

改 `canvas.width` / `canvas.height` 会让 drawing buffer 重新分配并被清空，`program` / `buffer` / `attribute` 的绑定也可能失效。之后 `draw()` 如果没有重新绑定、也没有重绘，就会露出黑块。

更准确地说，这条 bug 稳定可见的那一半是 `prefers-reduced-motion: reduce` 分支：它只画一帧就 `return`，没有 `requestAnimationFrame` 循环。resize 把 buffer 清空之后，**没有任何人再重绘**，背景就直接黑掉。

**修复前的关键代码：**

```js
// 启动时绑定一次，之后再也不重放
gl.useProgram(prog);
gl.bindBuffer(gl.ARRAY_BUFFER, buf);
gl.enableVertexAttribArray(loc);
gl.vertexAttribPointer(loc, 2, gl.FLOAT, false, 0, 0);

function resize() {
  var w = Math.max(1, window.innerWidth);
  var h = Math.max(1, window.innerHeight);
  canvas.width = w;
  canvas.height = h;
  gl.viewport(0, 0, w, h);
}
window.addEventListener('resize', resize);
resize();

if (reduce) {
  draw(0); // 静止一帧
  return;  // 没有 rAF 循环
}
```

绑定只做了一次，resize 只改了尺寸和 viewport，没有重新绑定，也没有在静止模式下重绘。

## 改动落点 + 回归验证

**修复：**

```js
// canvas 尺寸改变会重置 context 状态，把绑定收成一个函数，resize 时重放
function bindState() {
  gl.useProgram(prog);
  gl.bindBuffer(gl.ARRAY_BUFFER, buf);
  gl.enableVertexAttribArray(loc);
  gl.vertexAttribPointer(loc, 2, gl.FLOAT, false, 0, 0);
}
bindState();

function resize() {
  var w = Math.max(1, window.innerWidth);
  var h = Math.max(1, window.innerHeight);
  canvas.width = w;
  canvas.height = h;
  gl.viewport(0, 0, w, h);
  bindState();          // 尺寸改变重置了状态，重新绑定
  if (reduce) draw(0);  // 静止模式下无 rAF 循环，resize 后必须手动重绘，否则黑屏
}
```

**改动范围**：只改 `bg-shader.js`，+23/−12 行。没有引入库，没有重写渲染层，没有动页面结构。

**回归验证**：用 CDP 模拟连续缩放

```
1920×1080 → 2560×1440 → 800×600 → 1440×1100
```

每种尺寸截全页图，确认：

- 背景全程保持暖纸底 + 四色晕染，没有黑色块
- 没有横向溢出
- 控制台没有报错

## 这条链证明了什么

**① 一句话症状也可以是精确的 bug report。**
“全屏放大或者缩小时”给出了触发条件，“有些颜色变成黑色”给出了可观察结果。没有截图，AI 也能复现——因为它先找的是 resize 路径，而不是猜。

**② 渲染 bug 不能靠读代码验收。**
AI 的验证不是“代码看起来对”，而是改视口 + 截图。这个项目的 `AGENTS.md` 也写了：必须在浏览器里实际打开验证，不能只读代码判断“应该能跑”。

**③ 根因是隐式状态，不是某个 `if` 写错。**
canvas 尺寸改变会重新分配并清空 drawing buffer，viewport 和绑定也不会自动回到可用状态；修法不是加判断，而是把绑定收成一个可重放的 `bindState()`，并在静止模式下补一次重绘。这类 bug 的特点是：代码“看起来”每个函数都对，错的是调用顺序和调用时机。

**④ 修复被收在一个文件里。**
没有借机重写渲染层，没有换库；+23/−12 行，回归范围可控。对一个正在演示的作品来说，最小修复比“重构一遍”更有价值。

**⑤ AI 没有把锅甩给环境。**
它没有说“你的浏览器/显卡有问题”，也没有说“偶现、无法复现”，而是先读 resize 路径，再给根因，再用四种尺寸截图验证。

### 看黑块

1. 打开 `../demo-shader/index.html`
2. F12 → ⋮ → More tools → Rendering
3. 把 `Emulate CSS media feature prefers-reduced-motion` 设为 `reduce`
4. **刷新页面**
5. 拖动窗口边缘，把宽度从约 1920 缩到约 800（或打开 DevTools 设备工具栏改宽度）

预期：

- `21d5824`（修复前）：背景出现黑色块/整片变黑
- 当前版本：背景保持暖纸底 + 四色晕染

> 这条复现路径已在 Chrome headless 中实测：`21d5824` 在 800×600 下四角像素为 `(0, 0, 0)`；当前版本同尺寸下四角仍是暖纸色（约 `238–246`），没有黑块。

**为什么要在 reduced-motion 下看**：正常动画模式下有 `requestAnimationFrame` 循环，resize 后下一帧可能就把画面补回来了，黑块只闪一下；静止模式只画一帧，resize 清空 buffer 后没人重绘，黑屏会停在那里。这条链的 bug 在两种模式下都存在，只是静止模式最容易看见。

> 如果浏览器禁用了 WebGL，页面会退化为纯 CSS 底色，这个 bug 不会出现——这是设计好的降级，不是修复。
